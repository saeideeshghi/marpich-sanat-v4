# تحویل فرانت‌اند به بک‌اند · ۱۲ اکتبر ۲۰۲۶

این پروژه فرانت‌اند آمادهٔ اتصال است؛ دیتابیس، اعتبارسنجی سرور، ارسال پیامک و ذخیرهٔ فرم‌ها در این مخزن پیاده‌سازی نشده‌اند. فایل‌های HTML ساخته‌شده و اجزای مشترک فعلی مبنای انتقال به Razor هستند. تغییرات ظاهری قبلی در همین سورس حفظ شده‌اند.

## ساخت و اجرا

در ویندوز پیش از `npm ci` سرورهای Vite و preview را ببندید؛ فایل باینری Tailwind/Sharp ممکن است توسط آن‌ها قفل باشد. بهینه‌سازی اولیهٔ تصاویر یک‌بار انجام و با هش محتوا در `.cache` ذخیره می‌شود. اجرای preview فقط خروجی ساخته‌شده را سرو می‌کند و تصاویر را دوباره آماده نمی‌کند.

```powershell
npm ci
npm run check
npm run check:assets
npm run check:security
npm run check:performance
npm run format:check
npm run build:backend
npm run preview:backend -- --port 4174
```

خروجی مخصوص بک‌اند در `dist/backend` است. ویرایشگر طراحی، صفحهٔ مرجع توکن‌ها و تنظیمات قابل‌ویرایش آن‌ها در این خروجی منتشر نمی‌شوند. `build:pages` همچنان خروجی مستقل GitHub Pages می‌سازد. هر دو دستور پوشهٔ خروجی خود را بازسازی می‌کنند؛ برای تحویل، `build:backend` را در پایان اجرا کنید.

| فایل خروجی                                 | کاربرد                                                                              |
| ------------------------------------------ | ----------------------------------------------------------------------------------- |
| `page-assets.json`                         | ترتیب واقعی CSSها و ورودی JS هر یک از ۱۲ صفحه؛ CSSها باید در head بارگذاری شوند     |
| `.vite/manifest.json`                      | ورودی‌ها، importها و نام‌های هش‌دار؛ پیش‌بارگذاری importهای مشترک برای اولین بازدید |
| `assets/image-manifest.json`               | مسیر اصلی تصویر → نسخهٔ کم‌حجم؛ هنگام رندر CMS از نسخهٔ ثبت‌شده استفاده کنید        |
| `security-headers.json`                    | سیاست بررسی‌شدهٔ مرورگر؛ این هدرها باید توسط وب‌سرور واقعی نیز ارسال شوند           |
| `assets/customizer/template-overrides.css` | استایل تأییدشدهٔ طرح؛ پس از CSSهای صفحه بارگذاری شود                                |

HTML خامِ ریشه را مستقیماً سرو نکنید؛ includeها فقط هنگام build پردازش می‌شوند. فایل‌های CSS را به اجرای JavaScript وابسته نکنید. دارایی‌ها و manifest باید در یک release اتمیک منتشر شوند. فایل‌های هش‌دار CSS/JS را با `Cache-Control: public, max-age=31536000, immutable`، HTML را با revalidation و پاسخ‌های API حساس را با `no-store` سرو کنید. برای HTML، CSS، JS، JSON و SVG فشرده‌سازی Brotli/Gzip فعال شود. هدر HSTS فقط روی HTTPS واقعی فعال شود.

## قراردادهای اتصال

برای حفظ اولویت پترن هدر در Razor، لینک‌های `rel="modulepreload"` خروجی HTML همان صفحه را نیز منتقل کنید؛ `modulePreloads` و `imagePreloads` در `page-assets.json` ثبت شده‌اند. ماژول پترن هدر در صفحهٔ اصلی خانه استفاده نمی‌شود و نباید آنجا preload شود. پترن ثابت `/assets/decorations/page-pattern.svg` زودتر دریافت و تصویر اصلی خانه با `fetchpriority="high"` بارگذاری می‌شود. دریافت عکس اصلی را به تمام‌شدن اجرای پترن وابسته نکنید؛ تصاویر خارج از نمایش اولیه می‌توانند lazy بمانند.

راهنمای مدل‌ها و قالب‌های Razor در [BACKEND-INTEGRATION.md](BACKEND-INTEGRATION.md) و قراردادهای فعلی در [README.md](../README.md) قرار دارند.

- خروجی `backend` ورود را در حالت API واقعی قرار می‌دهد. مقصد پیش‌فرض `/api/auth` و پنج عملیات `login`، `register`، `request-code`، `verify-code` و `reset-password` هستند. در صورت سرویس جداگانه، reverse proxy هم‌دامنه تنظیم شود؛ ارسال رمز یا کد تأیید به دامنهٔ دیگر مسدود است.
- سرور باید `<meta name="csrf-token" content="...">` را رندر کند و هدر `X-CSRF-TOKEN` را اعتبارسنجی کند. درخواست بدون توکن ارسال نمی‌شود. سشن با کوکی `HttpOnly; Secure; SameSite` نگهداری شود. فرانت‌اند سشن/رمز/OTP را در localStorage ذخیره نمی‌کند؛ رویداد `auth:success` جایگزین مجوز سمت سرور نیست.
- `consultation:submit` و `rfq:submit` دادهٔ `FormData` همان فرم را تحویل می‌دهند. adapter باید رویداد را با `preventDefault()` بگیرد و وضعیت ارسال/خطا/موفقیت را نمایش دهد. ارسال واقعی تا نصب adapter انجام نمی‌شود. نوع درخواست و فایل پیوست سمت سرور دوباره بررسی شوند.
- لینک دیتاشیت/CAD فقط وقتی فایل واقعی و مجاز موجود است توسط CMS رندر شود. دکمهٔ فعلی `product:document-request` با `{ kind, button }` منتشر می‌کند و تا آن زمان پیام نبود فایل نشان می‌دهد؛ لینک دانلود جعلی حذف شده است.
- ۷۵ لینک placeholder موجود مربوط به محتوای تکمیل‌نشده و قراردادهای CMS هستند؛ در انتشار واقعی باید برای محتوای موجود URL معتبر ساخته شود. خصوصاً صفحهٔ جزئیات مقاله در این سورس وجود ندارد. صفحات جزئیات عمومیِ نمونه، مقصد اختصاصی تمام رکوردهای CMS نیستند.

سرور مسئول محدودسازی OTP/ورود، انقضای challenge و reset token، مجوز دانلود، پاک‌سازی Rich Text، اعتبارسنجی و اسکن فایل، محدودیت اندازه و نوع MIME واقعی، کنترل دسترسی و ثبت امن رویدادها است. tokenهای CSRF، رمز، فایل خصوصی یا کلید API را در متغیرهای `VITE_*` یا فایل‌های خروجی عمومی قرار ندهید.

## اصلاحات و شواهد

- پیش‌بارگذاری بدون شرط TTF حذف شد. فونت‌های WOFF2 با همان خانواده/وزن/گلیف تولید می‌شوند و طبق مصرف CSS دانلود می‌شوند.
- نسخه‌های WebP و عکس‌های داخل SVG به صورت lossless تولید می‌شوند. فایل‌های اصلی مالک تغییر نمی‌کنند؛ دادهٔ قابل‌تبدیل در بررسی محلی از ۲۰۰٬۲۷۶٬۰۱۱ به ۱۱۷٬۹۸۳٬۸۶۸ بایت کاهش یافت. RGB پیکسل کاملاً شفاف ممکن است توسط WebP حذف شود؛ آلفا و پیکسل‌های قابل‌نمایش حفظ می‌شوند.
- دادهٔ پترن هدر از ۱۱۲٬۸۸۵ به ۲۵٬۵۳۰ بایت و فوتر از ۱۰۹٬۷۸۹ به ۴۵٬۱۷۵ بایت، بدون تغییر تنظیمات/مسیرها، کم شد. دادهٔ فوتر تنها نزدیک نمایش فوتر بارگذاری می‌شود؛ شروع هدر منتظر idle تا ۸۰۰ میلی‌ثانیه نمی‌ماند.
- محاسبات کارت‌ها و badgeها از تغییر DOM جدا و دسته‌بندی شد؛ header در هر فریم اسکرول استایل را دوباره اندازه نمی‌گیرد. زمان‌بندی بازگشت محصولات هم‌زمان با برگشت گرید است.
- حرکت تصویر و سطح موقت دسته‌بندی با `transform` انجام می‌شود؛ نسبت طبیعی تصویر در رفت‌وبرگشت حفظ می‌شود. ارتفاع نهایی گرید در لحظهٔ تحویل ثابت می‌ماند.
- مسیر خصوصی ابزار طراحی پیش از کنترل‌های داخلی Vite پاسخ می‌داد. اکنون Host، مبدأ کامل و اتصال loopback پیش از خواندن توکن یا ذخیره بررسی می‌شوند؛ درخواست با Host جعلی در آزمون HTTP واقعی رد شد. `.cache` و پوشه‌های خصوصی از سرو فایل توسعه مستثنا شده‌اند. UTF-8 تکه‌تکه نیز بدون خرابی متن فارسی بازسازی می‌شود.
- مختصات، تعداد موج و دامنهٔ واردشده پیش از آماده‌سازی SVG محدود می‌شوند؛ اعداد بسیار بزرگ که باعث محاسبات سنگین می‌شدند رد می‌شوند.
- SVGهای موجود شامل ۳۲۳ مسیر معتبر هستند. رشتهٔ گزارش‌شدهٔ `tc0.2...` در سورس پیدا نشد و خطا در مرورگر آزمایشی بدون افزونه تکرار نشد. jQuery وابستگی پروژه نیست. validator اکنون رشتهٔ مشابه را پیش از ذخیره/نمایش پترن رد می‌کند؛ برای تشخیص منبع خارجی، URL کامل فایل خطادار در DevTools لازم است.
- npm audit در بررسی رجیستری آسیب‌پذیری شناخته‌شده‌ای گزارش نکرد. این نتیجه ضمانت امنیت سرویس بک‌اندِ هنوز ساخته‌نشده نیست.

گزارش اندازه‌گیری و نتیجهٔ مرورگر در [RELEASE-VERIFICATION.md](RELEASE-VERIFICATION.md) ثبت می‌شود. نتایج محلی با کش غیرفعال، زمان سایت روی هاست واقعی را تضمین نمی‌کنند؛ هاست، شبکه و تنظیمات کش/فشرده‌سازی نیز باید در staging بررسی شوند.
