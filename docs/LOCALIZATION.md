# ساختار سه‌زبانهٔ مارپیچ صنعت

نسخهٔ مرجع 4.1.0 از همان ۱۲ صفحهٔ موجود ساخته می‌شود. فارسی در ریشه، انگلیسی در `/en/` و عربی در `/ar/` قرار دارد. نمونه: `/products.html`، `/en/products.html` و `/ar/products.html`. هیچ سایت یا صفحهٔ خانهٔ جداگانه با معماری متفاوت ساخته نشده است.

## منابع قابل ویرایش

| بخش                | مسیر و روش                                                                 |
| ------------------ | -------------------------------------------------------------------------- |
| قالب صفحه          | HTML ریشه، `src/components` و `src/data/pages`؛ تغییر ساختار فقط یک بار    |
| متن انگلیسی و عربی | `src/i18n/en.json` و `ar.json`؛ کلید، متن فارسی یکدست‌شده است              |
| فهرست متن‌ها       | `src/i18n/source.json`؛ هر کلید باید در هر دو فرهنگ ترجمه باشد             |
| متن‌های تعاملی     | `src/i18n/runtime-source.json`؛ متن‌های فرم، خطا، فیلتر، مقاله و دسته‌بندی |
| مسیرهای واقعی      | `build/pages.js`؛ `pages` برای ۱۲ قالب و `allPages` برای تمام ۳۶ مسیر      |
| تولید HTML         | `build/html-partials.js` و `build/localization.js`                         |
| جهت انگلیسی و فونت | `build/locale-output.js` و `src/css/locales/en-fonts.css`                  |
| تغییر زبان         | `src/js/components/language.js`؛ همان نام صفحه و anchor حفظ می‌شود         |

فایل‌های `en/*.html` و `ar/*.html` فقط ورودی ساخت‌اند. HTML نهایی از قالب اصلی تولید می‌شود؛ آن‌ها را به کپی مستقل از محتوای فارسی تبدیل نکنید. فایل‌های `dist` خروجی‌اند و منبع ویرایش نیستند.

## روش افزودن یا اصلاح متن

۱. متن اصلی را در قالب، داده یا کد اصلی اصلاح کنید. مقدارهای فنی مانند `data-*`، شناسه‌ها، مقدار select و قرارداد API را ترجمه نکنید.

۲. کلید متن فارسی جدید را با فاصله‌های یکدست در `source.json` و ترجمهٔ آن را در هر دو فرهنگ ثبت کنید. متن‌های JavaScript را نیز در `runtime-source.json` ثبت کنید. پارامترهای متن پویا مانند `{0}` باید در ترجمه حفظ شوند.

۳. `npm run check:localization` و `npm run check:release` را اجرا کنید. متنِ بدون ترجمه باعث خطای ساخت می‌شود؛ جایگزین خاموش با فارسی وجود ندارد.

۴. هر سه نسخهٔ همان صفحه را در موبایل و دسکتاپ باز کنید. افزوده‌شدن صفحهٔ جدید به ورودی HTML هر دو زبان نیز نیاز دارد.

## رفتار و امنیت

HTML در زمان ساخت ترجمه و escape می‌شود. پیام‌های تعاملی با تحلیل AST رشته‌های JavaScript به lookup مشترک متصل می‌شوند؛ فایل‌های سورس فارسی بازنویسی نمی‌شوند. شناسه‌ها و کلیدهای API ثابت‌اند. نگاشت رقم‌های OTP ترجمه نمی‌شود. پارامترهای عددی پیام عربی از سیستم رقم `arab` استفاده می‌کنند.

هر صفحهٔ ترجمه‌شده فقط فرهنگ کوچک پیام‌های تعاملی را به‌صورت JSON امن دریافت می‌کند؛ متن‌های صفحه مستقیماً در HTML هستند. فرهنگ کامل ۱۱۶۴ پیامی در زمان اجرا دانلود نمی‌شود. صفحهٔ فارسی فرهنگ ترجمه دریافت نمی‌کند. ترجمه از سرویس خارجی و تغییر متن پس از بارگذاری DOM انجام نمی‌شود.

مسیرهای داخلی همان زبان را حفظ می‌کنند؛ تغییر زبان، صفحه و anchor جاری را حفظ می‌کند. پارامترهای query که ممکن است مختص زبان یا فرم باشند منتقل نمی‌شوند. لینک‌های تماس، فایل و تصاویر تغییر زبان نمی‌کنند.

## ظاهر و فونت

فارسی و عربی همان CSS و تنظیمات ذخیره‌شده را دارند. CSS انگلیسی از یک کپی خروجی تولید می‌شود: جهت، تراز، فاصله‌ها، گوشه‌ها و گرادیان‌های افقی مناسب LTR می‌شوند. فایل اصلی و تنظیمات فارسی تغییر نمی‌کنند. فلش‌های جهت‌دار انگلیسی مستقل از تصاویر محتوایی برمی‌گردند. overrideهای نهایی انگلیسی در فایل مخصوص همان زبان‌اند. توسعه و ساخت هر دو همین تبدیل را دارند.

| زبان    | تیتر               | متن و زیرتیتر |
| ------- | ------------------ | ------------- |
| فارسی   | Peyda موجود        | Peyda موجود   |
| عربی    | Peyda موجود        | Peyda موجود   |
| انگلیسی | Montserrat 600/700 | D-DIN 400/700 |

فونت‌های انگلیسی از مجموعهٔ ارائه‌شدهٔ کاربر در `public/fonts/en` کپی شده‌اند. Montserrat و D-DIN در نسخهٔ نمایشی به WOFF2 تبدیل می‌شوند؛ فایل‌های اصلی TTF و OTF بازنویسی نمی‌شوند. نام Yekan Bakh در فایل‌های بررسی‌شده پیدا نشد؛ فونتی با نام مشابه جایگزین آن نشده است. Montserrat و D-DIN حروف عربی لازم را ندارند، بنابراین متن عربی با Peyda نمایش داده می‌شود. اصل فونت‌ها و مجموعهٔ مرتب‌شدهٔ قبلی حفظ شده‌اند.

## اتصال بک‌اند

ساخت `npm run build:backend` هر ۳۶ نما و `page-assets.json` را تولید می‌کند. برای دریافت CSS/JS هر مسیر، همان ورودی مسیر را در manifest بخوانید؛ وابستگی‌های زبان‌ها alias جدا دارند تا CSS انگلیسی روی فارسی اعمال نشود. ابزار طراحی در این خروجی عمومی نیست.

قرارداد فرم‌ها، ورود، OTP و رویدادهای کاتالوگ مشترک است. زبان رابط، سرویس واقعی ارسال فرم، SMS، دانلود مدارک یا CMS ایجاد نمی‌کند. این اتصال‌ها همان موارد باز قبلی‌اند؛ به `BACKEND-INTEGRATION.md` مراجعه کنید. تولید خودکار تغییرات ترجمه یا ذخیرهٔ زبان در حساب کاربری فعلاً تعریف نشده است.

## بررسی‌ها

```powershell
npm run check:release
npm run build
npm run check:build
npm run build:backend
npm run preview:backend -- --port 4180
```

برای بررسی مرورگر باید Chrome یا Edge با CDP محلی و پروفایل آزمایشی جدا اجرا شود. سپس در ترمینال دیگر:

```powershell
$env:SITE_URL = 'http://127.0.0.1:4180/'
$env:CDP_URL = 'http://127.0.0.1:9227'
node scripts/check-browser.js
npm run check:browser:locales
```

آزمون اول کنترل‌های رفتاری و هندسهٔ نسخهٔ فارسی را پوشش می‌دهد. آزمون دوم هر ۳۶ مسیر را در عرض‌های ۱۵۰۰ و ۳۹۰، زبان، جهت، فونت، لینک‌های داخلی، متن انگلیسی، overflow و خطاهای کنسول بررسی می‌کند و تعامل‌های ترجمه‌شده را اجرا می‌کند. همین آزمون برای سرور توسعه نیز با تغییر `SITE_URL` اجرا می‌شود. گزارش‌ها و تصاویر در `.cache` می‌مانند.
