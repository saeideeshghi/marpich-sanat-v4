**گزارش بررسی امنیت، باگ و بارگذاری — ۱۲ اکتبر ۲۰۲۶**

بررسی روی سورس فعلی، هر ۱۲ صفحه، خروجی بک‌اند و خروجی GitHub Pages انجام شد. تنظیمات انیمیشن محصولات، چیدمان و فایل‌های اصلی تصاویر حفظ شدند. انتشار یا تغییر روی مخزن آنلاین انجام نشد.

اصلاحات انجام‌شده:

- تصویر اصلی و عکس‌های بزرگِ کارت‌ها نسخه‌های متناسب با اندازهٔ نمایش دارند. مرورگر با `srcset` و `sizes` نسخهٔ مناسب را انتخاب می‌کند. عکس‌ها با WebP کیفیت ۹۲ و آلفای کامل تحویل داده می‌شوند؛ فایل اصلی و نسخهٔ کاملِ قبلی باقی می‌مانند. تصاویر فنی محصولات همچنان بدون افت کیفیت فشرده می‌شوند.
- نام نسخه‌های جدید تصویر شامل هش محتواست؛ تعویض عکس باعث استفاده از نسخهٔ قدیمیِ کش نمی‌شود. تصاویر غیرضروری با `loading="lazy"` بارگذاری می‌شوند و تصویر اصلی با اولویت بالا دریافت می‌شود.
- خروجی عمومی سیاست CSP دارد؛ اجرای اسکریپت تزریقیِ inline در مرورگر GitHub Pages آزمایش و مسدود شد. محیط توسعه این سیاست را دریافت نمی‌کند تا HMR و ابزار تنظیمات کار کنند. جلوگیری از نمایش سایت داخل iframe همچنان به هدر پاسخِ سرور نیاز دارد.
- پاسخ ورود باید شناسهٔ چالش و توکن بازیابیِ رشته‌ایِ معتبر داشته باشد. پاسخ‌های اشتباه پذیرفته نمی‌شوند و پیام‌های غیررشته‌ایِ سرور نمایش داده نمی‌شوند. مقدار نامعتبر یا بی‌نهایتِ زمان انتظار نمی‌تواند شمارنده را خراب کند. هدر `Retry-After` با ثانیه یا تاریخ پردازش می‌شود؛ این دو قالب در [مرجع HTTP](https://httpwg.org/specs/rfc9110.html#field.retry-after) تعریف شده‌اند.
- بررسی کلیدهای خصوصی از فایل‌های ریشه به سورس، اسکریپت‌ها، ابزار ساخت، مستندات و workflow گسترش یافت. فایل‌های کلید و پوشه‌های محلی حساس به `.gitignore` اضافه شدند؛ این کار فایل‌های حساسِ از قبل ثبت‌شده در تاریخچهٔ Git را پاک نمی‌کند.
- دستور `npm run check:release` همهٔ بررسی‌های سورس، امنیت، فایل‌ها، عملکرد و قالب‌بندی را اجرا می‌کند. اسکریپت انتشار و GitHub Actions از همین کنترل استفاده می‌کنند. Actions همچنین آسیب‌پذیری‌های وابستگی‌ها را بررسی می‌کند.
- مجوز نوشتن Pages و صدور توکن هویت فقط به job انتشار داده شد؛ job ساخت مجوز خواندن دارد. این جداسازی مطابق توصیهٔ [GitHub دربارهٔ کمترین مجوز لازم برای هر job](https://docs.github.com/en/actions/reference/security/secure-use) است.

برای مرحلهٔ بک‌اند هنوز موارد مشخص زیر باز هستند:

- ۷۵ لینک نمایشی `#` در صفحات وجود دارد که مقصد واقعی آن‌ها باید از محتوای نهایی/CMS بیاید.
- فرم مشاوره، استعلام، ادامهٔ فهرست‌ها، فایل‌های فنی و مقصد شبکه‌های اجتماعی هنوز قرارداد اتصال دارند؛ این مخزن سرویس واقعی آن‌ها را پیاده نکرده است.
- ورود واقعی به API، توکن CSRF و کوکی نشست سرور نیاز دارد. محدودیت درخواست، مجوز دسترسی، اعتبارسنجی فایل، بررسی نوع واقعی فایل و نگهداری امن آن باید در سرور اجرا و تست شوند. تست فعلی ورود از پاسخ HTTP آزمایشی استفاده می‌کند.
- هدرهای `dist/backend/security-headers.json` باید روی پاسخ سرور واقعی اعمال شوند. فایل‌های JS/CSS و تصاویر دارای هش می‌توانند کش بلندمدت داشته باشند؛ فایل‌های بدون هش باید با ETag و اعتبارسنجی مجدد تحویل شوند. Brotli/Gzip و زمان پاسخ نیز باید روی میزبان واقعی بررسی شوند.

برای بررسی مجدد سورس `npm run check:release` و برای ساخت، یکی از `npm run build:backend` یا `npm run build:pages` را اجرا کنید. بررسی مرورگر با `node scripts/check-browser.js` به Chrome دارای CDP و preview بک‌اند نیاز دارد؛ آدرس‌ها با `CDP_URL` و `SITE_URL` قابل تغییرند.
