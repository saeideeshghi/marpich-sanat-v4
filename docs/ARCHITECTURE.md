# معماری و راهنمای کد مارپیچ صنعت V4

این سند ساختار فعلی هر ۱۲ صفحه و خروجی‌های انتشار را توضیح می‌دهد. پروژه یک Frontend چندصفحه‌ای فارسی و RTL است؛ هر صفحه HTML و ورودی JavaScript مستقل دارد. پردازش HTML، Tailwind و خروجی انتشار با Vite انجام می‌شود. پایگاه داده، ارسال واقعی فرم‌ها و پنل مدیریت محتوا هنوز در این بسته پیاده‌سازی نشده‌اند.

## ۱. اجرا، ویرایش و خروجی

Node.js حداقل 22.12.0 لازم است. دستورات را در پوشه‌ای اجرا کنید که package.json قرار دارد:

```powershell
npm ci
npm run dev
```

فایل‌های HTML خام را با دوبار کلیک یا Live Server اجرا نکنید؛ includeهای مشترک و CSS باید از مسیر Vite پردازش شوند. برای کاستومایزر:

```powershell
npm run customize
```

ویرایشگر در مسیر /tools/customizer.html باز می‌شود. در ویندوز CUSTOMIZE.cmd همین کار را انجام می‌دهد.

| دستور                  | کاربرد                                                        |
| ---------------------- | ------------------------------------------------------------- |
| npm run check          | کنترل ساختار ۱۲ صفحه، کامپوننت‌ها، قراردادهای رفتار و تنظیمات |
| npm run format:check   | کنترل یکدستی قالب کد                                          |
| npm run check:assets   | گزارش تصاویر و فونت‌های مفقود در سورس                         |
| npm run build          | ساخت با Base برابر / برای اجرای معمولی یا Backend             |
| npm run build:pages    | ساخت با پیشوند مخزن GitHub و کنترل لینک‌های خروجی             |
| npm run preview:pages  | اجرای محلی آخرین خروجی Pages                                  |
| npm run publish:github | Check، Build، Commit و Push طبق تنظیمات مخزن                  |
| npm run tokens:refresh | به‌روزرسانی قرارداد متغیرهای طراحی بعد از تغییر تعریف متغیرها |

پوشه‌های تصاویر و فونت‌های پروژهٔ فعلی را هنگام جایگزینی این ZIP نگه دارید. این تحویل سورس است؛ node_modules، dist، فایل‌های حجیم تصاویر و فایل‌های آزمایشی در آن قرار نمی‌گیرند. خروجی Build بعد از اضافه‌بودن Assetهای واقعی ساخته می‌شود.

## ۲. مسیر پردازش صفحه

فهرست صفحات در build/pages.js ثبت شده است. Vite هر فایل HTML ریشه را می‌خواند؛ build/html-partials.js کامپوننت‌های مشترک و دادهٔ JSON همان صفحه را جایگزین includeها می‌کند. سپس Vite ورودی JS صفحه و دو لینک CSS در head را پردازش می‌کند. main.css پایهٔ مشترک است و src/css/entries/<page>.css ترتیب استایل‌های اختصاصی صفحه را حفظ می‌کند؛ هیچ‌کدام به اجرای JS وابسته نیستند. پلاگین کاستومایزر CSS تنظیمات ذخیره‌شده را به خروجی اضافه می‌کند.

```html
<!-- @include header -->
<!-- @include product-cards products -->
<!-- @include footer -->
```

این عبارت‌ها دستور Build هستند. مرورگر یا ASP.NET Core آن‌ها را به‌صورت مستقیم اجرا نمی‌کند. کامپوننت بدون کلید، مثل header، از src/components خوانده می‌شود؛ کامپوننت دارای کلید، مثل products، داده را از src/data/pages/products.json می‌گیرد. build/components.js متن و URLهای این داده‌ها را بررسی و Escape می‌کند.

همهٔ محتوای صفحه داخل JSON نیست. مثلاً تاریخچهٔ درباره ما، بخش‌هایی از جزئیات پروژه، کارت‌های صنایع و کارت‌های مقاله هنوز در HTML ریشه نوشته شده‌اند. برای مهاجرت به CMS، هم HTML و هم JSONهای مرتبط باید بررسی شوند.

دارایی‌های عمومی ابتدا در `build/public-assets.js` بررسی و در کش متعلق به همان پردازش کپی می‌شوند. فایل خصوصی، لینک فایل‌سیستم و SVG دارای کد اجرایی پذیرفته نمی‌شود. `build/optimized-assets.js` نسخه‌های تصویری و ابعاد HTML را می‌سازد؛ `build/svg-photos.js` فقط SVGهای عکاسی شناخته‌شده را به نسخه‌های WebP بدون افت تبدیل می‌کند. `build/icon-fonts.js` در تولید فونت و قواعد مصرف‌نشدهٔ Font Awesome را حذف می‌کند و در توسعه مجموعهٔ کامل را برای ویرایش زنده نگه می‌دارد. سورس اصلی تغییر نمی‌کند؛ کش موقت عمومی در پایان همان Build پاک می‌شود. جزئیات سنجش و محدودیت‌ها در [گزارش بررسی](AUDIT-2026-10-14.md) آمده‌اند.

## ۶. قرارداد ریسپانسیو و ترتیب استایل

| بازه                      | عرض                         |
| ------------------------- | --------------------------- |
| موبایل                    | تا 639px                    |
| تبلت                      | از 640 تا 1179px            |
| دسکتاپ                    | از 1180px                   |
| موبایل کوچک در Customizer | تا 450px؛ زیرمجموعهٔ موبایل |
| بازهٔ دلخواه              | Min/Max شامل خود مرزها      |

head صفحه ابتدا main.css و سپس src/css/entries/<page>.css را لینک می‌کند. فایل CSS ورودی صفحه، CSS اختصاصی، content-flow و سپس responsive.css را به همان ترتیب قبلی Import می‌کند. درباره ما، about-team.css را بعد از لایهٔ ریسپانسیو وارد می‌کند تا هندسهٔ قاب مستقل بماند. در خروجی، template-overrides.css بعد از CSSهای اصلی بارگذاری می‌شود. قوانین ذخیره‌شده از !important استفاده می‌کنند؛ تغییر فایل پایه ممکن است زیر یک تنظیم ذخیره‌شده دیده نشود.

body[data-page] محدودهٔ امن تغییرات اختصاصی است. کلاس CSS را برای ظاهر و data-* را برای رفتار نگه دارید. برای تغییر یک بخش از یک صفحه، قانون را روی همان صفحه و بخش بنویسید؛ Header، Footer و فرم‌های مشترک را بدون بررسی سایر مصرف‌کننده‌ها تغییر ندهید.

## ۷. تنظیم جدید تصویر درباره ما

در Customizer، صفحهٔ «درباره ما» را انتخاب کنید. زیر «تصویر اصلی درباره ما»، پنل «تنظیم سریع تصویر در هر اندازه» قرار دارد. ابتدا همهٔ اندازه‌ها یا یکی از دسکتاپ، تبلت و موبایل را انتخاب کنید؛ هر فیلد پس از پایان ویرایش یا تغییر انتخاب اعمال می‌شود.

| کنترل سریع  | رفتار                                                          | مقصد تنظیم                        |
| ----------- | -------------------------------------------------------------- | --------------------------------- |
| فایل تصویر  | مسیر /assets/... یا URL کامل؛ امکان فایل متفاوت برای هر اندازه | about-image / image-source        |
| عرض بخش     | درصد، مقدار px یا عدد ساده به معنی درصد                        | about-image-container / width     |
| حداکثر عرض  | عدد px یا none                                                 | about-image-container / max-width |
| ارتفاع قاب  | عدد px یا auto                                                 | about-image-frame / height        |
| نسبت قاب    | مثلاً 16 / 9؛ در ارتفاع auto اندازهٔ قاب را تعیین می‌کند       | about-image-frame / aspect-ratio  |
| نمایش تصویر | contain برای نمایش کامل؛ cover برای پرکردن و برش قاب           | about-image / object-fit          |
| جای تصویر   | دو درصد، ابتدا افقی سپس عمودی؛ مثلاً 50% 30%                   | about-image / object-position     |
| زوم تصویر   | 100 برای حالت عادی، 110 برای بزرگ‌نمایی ده درصد                | about-image / scale               |
| گردی قاب    | مقدار px                                                       | about-image-frame / border-radius |

مثال شروع تنظیم: در موبایل ارتفاع 220px و نسبت 16 / 9، در تبلت ارتفاع 340px و در دسکتاپ ارتفاع 500px را امتحان کنید؛ این‌ها مثال‌اند و به‌صورت پیش‌فرض در این تحویل ثبت نشده‌اند. در cover جای تصویر را با درصدها تنظیم کنید تا صورت‌ها یا بخش مهم تصویر از قاب خارج نشوند. با contain تمام تصویر حفظ می‌شود و ممکن است بخشی از قاب خالی بماند.

فیلد خالی یا دکمهٔ ↺، فقط Override همان کنترل در همان اندازه را حذف می‌کند. Placeholder نتیجهٔ فعلی مرورگر است؛ اگر فیلد خالی است، مقدار از استایل پایه یا قانون عمومی به ارث می‌رسد. تنظیم همهٔ اندازه‌ها پایهٔ مشترک می‌سازد؛ تنظیم دستگاه، موبایل کوچک یا بازهٔ دلخواه می‌تواند روی آن مقدم شود. هر Min/Max اضافی را در انتخابگر عمومی «اندازه» تنظیم کنید.

ورودی مسیر، فایل را Upload نمی‌کند. ابتدا تصویر را در assets/images/about یا public/assets/images/about کپی کنید و سپس مسیر عمومی /assets/images/about/... را وارد کنید. در Pages پیشوند نام مخزن خودکار افزوده می‌شود. اگر فایل جدید لود نشود، تصویر اصلی about-team.svg نمایش داده می‌شود و پنل پیام خطا نشان می‌دهد.

فایل src/js/customizer/about-image-controls.js فقط یک رابط ساده روی همان مدل قوانین موجود است. مسیر Preview، Undo/Redo، Compare، Save و Export عوض نشده است. قوانین جدید همیشه به about محدود و مستقل از انتخاب عمومی «همه صفحه‌ها» هستند.

برای ذخیرهٔ واقعی در اجرای محلی، «تأیید و ثبت در قالب» را بزنید. روی Pages دسترسی نوشتن سورس وجود ندارد؛ ZIP تنظیمات را بگیرید، فایل‌های آن را کنار سورس جایگزین و دوباره Build/Publish کنید. ذخیرهٔ پیش‌نویس در مرورگر انتشار سایت محسوب نمی‌شود.

گالری درباره ما با Hover یا Focus لینک، فقط تصویر پس‌زمینه را 6% بزرگ می‌کند؛ لایهٔ Fade و متن ثابت می‌مانند. این رفتار برای دستگاه دارای Hover و اشاره‌گر دقیق فعال است. درخواست کاهش حرکت، انیمیشن را حذف یا طبق لایهٔ مشترک تقریباً فوری می‌کند. هندسهٔ اصلاح‌شدهٔ SVG گالری حفظ شده است.

## ۸. منابع تنظیمات و نکات نگهداری

build/customizer.js در Dev درخواست __customizer/settings را با Token همان نشست و Revision فایل کنترل می‌کند؛ ذخیره با Revision قدیمی رد می‌شود. این Endpoint ابزار توسعه است و API آمادهٔ پنل مدیریت Production نیست.

هنگام Build، CSS و settings.json در assets/customizer خروجی داده می‌شوند. فقط در about.html، JSON منابع تصویر در script با ID برابر mps-image-sources قرار می‌گیرد. customizer-image.js با Resize، منبع متناسب با عرض جدید را انتخاب می‌کند. در انتقال به Razor، هم CSS و هم این JSON باید حفظ یا با مدل CMS جایگزین شوند.

کلید اصلی قوانین شامل صفحه، Target، Breakpoint، حالت و در صورت وجود Range است. normalizeConfig و normalizeProperty قرارداد ورودی مشترک مرورگر و سرور توسعه‌اند. Export شامل تنظیمات، CSS تولیدی و دو فایل پترن است. CSS تولیدی را بدون تغییر settings ویرایش نکنید؛ Build بعدی آن را بازسازی می‌کند.

## ۹. موارد باقی‌مانده و کنترل تحویل

- ۱۱۴ لینک Placeholder در صفحات وجود دارد؛ مقصد CMS، مقاله، دانلود یا گالری باید برای هرکدام مشخص شود.
- فرم‌های درخواست و RFQ ذخیره یا ارسال واقعی ندارند؛ Backend باید نتیجهٔ قطعی ثبت را به UI برگرداند.
- API ورود در حالت Production تا پیکربندی غیرفعال است؛ OTP نمونه فقط در Dev استفاده می‌شود.
- جستجوی مقاله روی کارت‌های موجود محلی است؛ Load More و فیلتر کاتالوگ به سرویس واقعی نیاز دارند.
- پنل CMS، مدیریت رسانه، ترجمه، مدیریت درخواست‌ها و Session سمت سرور خارج از این Frontend هستند.

پس از تغییرات، Check، Format و Build را اجرا کنید. با Assetهای کامل، check:assets را هم اجرا کنید. مرزهای 639/640 و 1179/1180، متن فارسی بلند، جدول فنی، منوی باز، صفحهٔ تماس و Hover کارت‌ها را بررسی کنید. تغییرات این تحویل به CSS درباره ما، UI کاستومایزر و مستندات محدود شده‌اند؛ تنظیمات قبلی و فایل‌های سایر صفحات حفظ می‌شوند.
