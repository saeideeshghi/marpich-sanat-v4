# راهنمای فایل‌ها و پوشه‌های مارپیچ صنعت

> به‌روزرسانی 4.1.0: همین ۱۲ قالب اکنون در سه زبان و ۳۶ مسیر ساخته می‌شوند. ساختار زبان‌ها و manifest در [LOCALIZATION.md](LOCALIZATION.md) و نتیجهٔ بررسی این نسخه در [RELEASE-4.1.0.md](RELEASE-4.1.0.md) توضیح داده شده است.

مرجع کامل و به‌روز این تحویل [backend-handoff.html](backend-handoff.html) است. ابزار انتشار اختصاصی از این نسخه حذف شده؛ این راهنما محل ویرایش سورس را توضیح می‌دهد.

این راهنما برای ادامهٔ ویرایش همین پروژه است. پروژه یک سایت فرانت‌اند چندصفحه‌ای با HTML، CSS و JavaScript است؛ Vite فایل‌ها را پردازش می‌کند و Tailwind بخشی از استایل‌ها را می‌سازد. بک‌اند، دیتابیس، CMS و ارسال واقعی فرم‌ها هنوز باید جداگانه پیاده‌سازی و متصل شوند.

## از کدام پوشه ادامه بدهم؟

ویرایش را روی فایل‌های اصلی این پوشه انجام بده. `dist`، `node_modules`، `.cache` و کپی‌های موجود در پوشهٔ تحویل، محل ویرایش سورس نیستند.

فایل `.env.example` به‌خودی‌خود اتصال بک‌اند را ایجاد نمی‌کند. هر تنظیمی که در خروجی فرانت‌اند قرار بگیرد برای مرورگر قابل مشاهده است؛ رمز و کلید خصوصی نباید در آن خروجی قرار داده شود.

## هر صفحه را کجا ویرایش کنم؟

ستون CSS زیر به `src/css/pages` و ستون JavaScript به `src/js/pages` اشاره دارد. فایل‌های هم‌نام در `src/css/entries` ترتیب بارگذاری CSS همان صفحه را تعیین می‌کنند.

| صفحه           | HTML ریشه               | CSS اختصاصی                                                                        | JavaScript                                      |
| -------------- | ----------------------- | ---------------------------------------------------------------------------------- | ----------------------------------------------- |
| صفحهٔ اصلی     | `index.html`            | `home.css`                                                                         | `home.js`                                       |
| محصولات        | `products.html`         | `products.css`، `products-featured.css`                                            | `products.js`، `products-motion.integration.js` |
| جزئیات محصول   | `product-details.html`  | `product-details.css`                                                              | `product-details.js`                            |
| دستهٔ هواساز   | `air-handling.html`     | `air-handling.css`                                                                 | `air-handling.js`                               |
| پروژه‌ها       | `projects.html`         | `projects.css`                                                                     | `projects.js`                                   |
| جزئیات پروژه   | `project-details.html`  | `project-details.css`، `project-details-theme.css`، `project-details-settings.css` | `project-details.js`                            |
| صنایع تحت پوشش | `industries.html`       | `industries.css`                                                                   | `industries.js`                                 |
| صنعت نساجی     | `industry-textile.html` | `industry-textile.css`                                                             | `industry-textile.js`                           |
| حوزه‌های تخصصی | `expertise.html`        | `expertise.css`                                                                    | `expertise.js`                                  |
| مقالات         | `articles.html`         | `articles.css`                                                                     | `articles.js`                                   |
| دربارهٔ ما     | `about.html`            | `about.css`، `about-team.css`                                                      | `about.js`                                      |
| تماس با ما     | `contact.html`          | `contact.css`                                                                      | `contact.js`                                    |

`build/pages.js` فهرست رسمی صفحات و وضعیت منوی هر صفحه را نگه می‌دارد. برای افزودن صفحهٔ جدید، فقط ساخت HTML کافی نیست؛ ورودی، CSS/JS و این فهرست نیز باید هماهنگ باشند. صفحهٔ جزئیات مقاله در فهرست فعلی وجود ندارد.

بخشی از محتوا مستقیماً در HTML و بخشی در JSON صفحه است. اگر متن موردنظر در HTML نبود، `src/data/pages` را بررسی کن. صفحهٔ تماس JSON هم‌نام ندارد و بخش اصلی فرم آن در HTML و JavaScript خودش است.

## ابزارها و راهنماهای دیگر

`tools/customizer.html` ابزار تنظیم ظاهر و `tools/design-tokens.html` مرجع متغیرهای طراحی است. حالت توسعه امکان ذخیرهٔ محلی دارد؛ خروجی استاتیک نمی‌تواند فایل سورس روی میزبان استاتیک را بنویسد و برای انتقال تنظیمات از خروجی ابزار استفاده می‌شود.

در `docs`، فایل `ARCHITECTURE.md` جزئیات معماری و نقشهٔ اتصال را دارد. `BACKEND-INTEGRATION.md`، `BACKEND-RELEASE.md` و `backend-handoff.html` برای تحویل به تیم بک‌اند هستند. راهنماهای `PRODUCTS-MOTION-FA.md` و `PATTERN-ANIMATION.md` دربارهٔ حرکت و پترن‌اند. گزارش‌های `AUDIT-*` و سایر فایل‌های تغییرات، شواهد و توضیحات مربوط به تاریخ درج‌شدهٔ خود را نگه می‌دارند؛ تنظیم زندهٔ برنامه از سورس و JSONهای فعلی خوانده می‌شود.

## اجرا و انتشار تغییرات بعدی

دستورها را در ریشهٔ پروژه اجرا کن، جایی که `package.json` قرار دارد:

```powershell
npm ci
npm run dev
```

`npm ci` برای نصب اولیه یا هماهنگ کردن وابستگی‌هاست و لازم نیست برای هر تغییر متن یا CSS تکرار شود. HTML را با آدرس اعلام‌شدهٔ Vite ببین؛ باز کردن مستقیم فایل با دوبار کلیک، پردازش کامپوننت‌ها و CSS را انجام نمی‌دهد.

| دستور                   | نتیجه                                                                   |
| ----------------------- | ----------------------------------------------------------------------- |
| `npm run customize`     | اجرای محلی ابزار طراحی                                                  |
| `npm run check:release` | اجرای مجموعه بررسی‌های سورس، امنیت، دارایی، عملکرد و قالب‌بندی          |
| `npm run build`         | خروجی معمولی با مسیر پایهٔ `/` در `dist`                                |
| `npm run preview`       | مشاهدهٔ محلی خروجی ساخت ساخته‌شده                                       |
| `npm run build:backend` | خروجی استاتیک تحویل به تیم بک‌اند در `dist/backend`؛ سرور تولید نمی‌کند |

این پوشه کنار پروژه قرار دارد و محل ادامهٔ توسعه نیست. پوشه‌های تاریخ‌دار آن، خروجی تحویل و شواهد بررسی همان نوبت را نگه می‌دارند:

| نام یا الگو                            | کاربرد                                                        |

| `before-*.zip`                         | پشتیبان قبل از اصلاحات همان نوبت                              |
| `pages-build.zip`                      | خروجی آمادهٔ انتشار Pages در زمان بسته‌بندی                   |

| `baseline*` و `after*`                 | تصاویر و اندازه‌گیری‌های قبل و بعد از اصلاحات                 |

## چند مثال برای پیدا کردن محل تغییر

- متن یا ترتیب بخش حوزه‌های تخصصی دربارهٔ ما: `about.html` و `src/css/pages/about.css`.
- رنگ متن CTAهایی که از قانون مشترک استفاده می‌کنند: `src/css/components/content-flow.css`؛ مقدار برند در `src/css/tokens.css` است.
- رنگ زمینهٔ ورودی‌های تماس: `src/css/pages/contact.css`؛ فرم و رفتار آن در `contact.html` و `src/js/pages/contact.js` هستند.
- تنظیمات انیمیشن دسته‌بندی: `src/data/product-motion/config.json`؛ موتور حرکت در `src/js/components/product-category-motion.js` است.
- محتوای FAQ نساجی: `src/data/pages/industry-textile.json`؛ قالب سؤال‌ها در `src/components/faq*.html` و استایل اختصاصی در `src/css/pages/industry-textile.css` است.
- هدر یا فوتر تمام صفحات: HTML متناظر در `src/components` و CSS/JS مربوط در پوشه‌های کامپوننت‌ها.

پس از تغییر کامپوننت مشترک، صفحات مصرف‌کننده را در اندازه‌های موبایل، تبلت و دسکتاپ بررسی کن؛ بررسی فقط همان صفحه‌ای که در آن کار می‌کنی کافی نیست.
