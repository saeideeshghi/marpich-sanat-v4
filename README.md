# مارپیچ صنعت · V4

## تحویل بک‌اند و اصلاحات سرعت/امنیت · ۱۲ اکتبر ۲۰۲۶

خروجی مخصوص اتصال بک‌اند با `npm run build:backend` در `dist/backend` ساخته می‌شود. [راهنمای تحویل](docs/BACKEND-RELEASE.md) شامل ترتیب دارایی‌ها، قرارداد فرم/ورود، مدارک و هدرهای امنیتی است. [گزارش بررسی](docs/RELEASE-VERIFICATION.md) اندازه‌گیری سرعت و پوشش آزمون‌ها را ثبت می‌کند. هشدار preload فونت حذف، تصاویر/فونت‌ها بهینه و ابزار طراحی از خروجی بک‌اند جدا شده است. API و CMS واقعی هنوز باید توسط تیم بک‌اند متصل شوند.

## تنظیمات تأییدشده و اصلاحات نهایی · ۱۱ اکتبر ۲۰۲۶

- عنوان CTA تصویری از ۱۰۲۵ تا ۱۴۸۰px، در تنظیمات ذخیره‌شده نیز ۲۲px است. فرم جستجوی مقالات به‌جای border بیرونی از خط داخلی استفاده می‌کند تا دکمه به لبهٔ بالا و چپ بچسبد.
- جزئیات بررسی و راهنمای جایگزینی در [docs/PRODUCTS-MOTION-FA.md](docs/PRODUCTS-MOTION-FA.md) است.

## بارگذاری استایل و حرکت محصولات · ۱۱ اکتبر ۲۰۲۶

- مسیر تصویری قبلی باز شدن از بالا راست بازگردانده شده است. حرکت باز شدن ۶۲۰ms و برگشت باکس ۴۸۰ms است؛ آماده‌سازی پترن مرحله‌ای است، فوتر خارج از دید ساخته نمی‌شود و پترن‌ها هنگام حرکت محصولات مکث می‌کنند.
- توضیحات حوزه‌های تخصصی از ۱۱۷۹px عرض ۵۱٪ و پایین‌تر عرض کامل دارند؛ متن پیوسته با سقف سه خط جای شکست خط دستی را می‌گیرد. فاصلهٔ زیاد تیتر و توضیح آخرین بخش تماس با تنظیم ردیف‌های گرید رفع شده است.
- جزئیات، محدودیت بررسی و راهنمای جایگزینی در [docs/PRODUCTS-MOTION-FA.md](docs/PRODUCTS-MOTION-FA.md) آمده است.

- عنوان و توضیح فرآیند همکاری وسط‌چین‌اند؛ Badge چندخطی ردیف کامل می‌گیرد. دکمه‌های محصولات خانه تا عرض ۱۲۲۷px زیر هم‌اند و آیکون همراه متن می‌آید.

## اجرا و کنترل

Node.js حداقل `22.12.0` لازم است. برای اجرای محلی:

```powershell
npm ci
npm run dev
```

HTML را مستقیم با دوبار کلیک یا Live Server باز نکن؛ پردازش includeها به Vite نیاز دارد.

```powershell
npm run check
npm run format:check
npm run check:assets
npm run build
npm run build:pages
npm run preview:pages
```

`check:assets` فایل‌های تصاویر و فونت‌های مفقود را گزارش می‌کند. پوشه‌های بزرگِ تصاویر در ZIP تحویل نیستند؛ مسیرهای واقعی قبلی در `assets`، `fonts` و `public` باید روی کامپیوتر صاحب پروژه حفظ و در مخزن جدید کپی شوند.

Breakpoints: موبایل تا ۶۳۹px؛ تبلت ۶۴۰–۱۱۷۹px؛ دسکتاپ از ۱۱۸۰px. ساخت Backend/محلی در `/` است؛ Build مخصوص Pages مسیر نام مخزن را اضافه می‌کند.

## مخزن جدید و انتشار خودکار

راهنمای کامل ویندوز، ساخت Repository، فعال‌کردن Pages و رفع خطاها در [GITHUB-UPLOAD.md](GITHUB-UPLOAD.md) است. برای مخزن جدید، ZIP را در یک پوشهٔ مستقل استخراج کن؛ `.git` قبلی را کپی نکن. تصاویر/فونت‌ها را با حفظ مسیرشان اضافه کن.

پس از ساخت مخزن خالی Public در GitHub، فقط یک بار:

```powershell
npm run github:setup -- --repo saeideeshghi/marpich-sanat-v4
```

برای ارسال اولیه و تمام آپدیت‌های بعدی:

```powershell
npm run publish:github
```

`PUSH-GITHUB.cmd` نیز همین انتشار را اجرا می‌کند. مقصد در `github-pages.json` ثبت می‌شود؛ Origin متفاوت پیش از Commit و Push رد می‌شود. اولین ارسال از مخزن خالی پشتیبانی می‌شود و آپدیت‌ها با Rebase معمولی انجام می‌شوند. Tag قدیمی جابه‌جا نمی‌شود.

در GitHub، Source در **Settings → Pages** باید **GitHub Actions** باشد. Workflow آمادهٔ `.github/workflows/pages.yml` بعد از Push به `main`، Check/Build و Deploy را انجام می‌دهد. مسیر Base در Actions از نام واقعی مخزن گرفته می‌شود؛ برای نام دیگری فقط همان نام را به `github:setup` بده.

فایل ZIP را کامل استخراج و محتویاتش را کنار `package.json` جایگزین کن؛ پوشهٔ `.github` نیز باید کپی شود. سورس HTML این پروژه به Vite نیاز دارد؛ انتشار مستقیم `main / (root)` باعث لودنشدن استایل‌های پردازش‌شده می‌شود. Workflow فقط خروجی ساخته‌شدهٔ `dist` را منتشر می‌کند. `build:pages` پیش از انتشار، لینک‌های CSS، استایل چانک‌های مشترک، فایل‌های JS و Base تمام ۱۴ ورودی را بررسی می‌کند. برای بررسی دوبارهٔ همین خروجی از `npm run check:pages` استفاده کن.


مسیر ویرایشگر `/tools/customizer.html` است؛ در ویندوز `CUSTOMIZE.cmd` نیز همین ابزار را اجرا می‌کند. تنظیمات صفحه، بخش مشترک یا المان دقیق، بازه‌های دلخواه، واحدهای CSS، Grid/Flex، رنگ، تایپوگرافی، تصویر، پترن، Undo/Redo و Export قابل ویرایش‌اند. راهنما در [CUSTOMIZER.md](CUSTOMIZER.md) است.

در اجرای محلی، ثبت تنظیمات فایل‌های سورس را می‌نویسد؛ در نسخهٔ Pages خروجی ZIP برای جایگزینی می‌دهد. تنظیمات اصلی در `src/data/customizer/settings.json`، پترن‌ها در `src/data/patterns` و CSS تولیدی در `src/css/template-overrides.css` هستند. CSS تولیدی را دستی ویرایش نکن؛ Build آن را از تنظیمات بازسازی می‌کند.

| مسیر                                       | کاربرد                                                          |
| ------------------------------------------ | --------------------------------------------------------------- |
| `src/components`                           | کامپوننت‌های HTML مشترک                                         |
| `src/data/pages`                           | محتوای کامپوننت‌های هر صفحه                                     |
| `src/js/pages` و `src/css/pages`           | ورودی و استایل اختصاصی هر صفحه                                  |
| `src/js/components` و `src/css/components` | رفتار و ظاهر مشترک                                              |
| `build`                                    | ترکیب HTML، Asset Base و تولید تنظیمات                          |
| `scripts`                                  | بررسی‌ها، پاکسازی و انتشار                                      |
| `public` و `assets`                        | فایل‌های استاتیک؛ خروجی Build آن‌ها را با مسیر مناسب کپی می‌کند |

پاکسازی فقط فهرست صریح `scripts/legacy-files.json` را بررسی می‌کند و به `docs` وابسته نیست:

```powershell
npm run clean:legacy
npm run clean:legacy -- --apply
```

فایل‌های مستندات قبلی در `docs` را می‌توانی حفظ کنی؛ این بسته آن پوشه را جایگزین نمی‌کند. راهنماهای معماری و اتصال Backend قبلی در همان مسیرهای `docs/ARCHITECTURE.md` و `docs/backend-handoff.html` باقی می‌مانند.
